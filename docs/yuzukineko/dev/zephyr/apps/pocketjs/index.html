PocketJS - JavaScript UI 应用

PocketJS 播放器通过 QuickJS-ng 和 Rust UI 核心／渲染器在 F101 上运行打包的 TypeScript／TSX 界面。默认应用是简单的 Solid 界面，同一 host 还可运行上游示例和本地渲染 benchmark。组件指南介绍模块接入、API、加速与所有权。

配套工程源码位置与一键编译​

项目说明
源码目录zephyr-components/pocketjs/samples/player
目标板级与模式yuzukineko_base · RAM（入口 0x40000000）
一期快速体验免编译直接烧录见 PocketJS 界面应用

在配套 f101-zephyr 工作区根目录直接执行（全部交叉工具链、依赖与子模块均已随包内置，无需 source env.sh 或手动 git submodule update）：

# 1. 一键编译（自动关联 yuzukineko_base 板级与对应 conf/overlay）
./.venv/bin/python scripts/build_apps.py --app pocketjs

# 2. 打包整片 SPI NOR 镜像：build/pocketjs/zephyr/zephyr-full.img
./.venv/bin/python scripts/pack_full_img.py --app pocketjs

生成的 build/pocketjs/zephyr/zephyr-full.img 可直接用 Windows 下的 LYNX Imager（主线 · SPI NOR）写入开发板，或在已透传 USB 的 WSL2 / Linux 终端执行 ./.venv/bin/python scripts/flash.py flash-full pocketjs（RAM 调试阶段也可用 ./.venv/bin/python scripts/flash.py run pocketjs 直接载入内存运行）。

当前 4.5.0 工程同步说明：配套工作区已内置 Bun 1.4.5（tools/bun）、Rust nightly-2026-07-02（tools/rust，含 rust-src）以及 PocketJS / QuickJS-ng 全部子模块与依赖；执行 scripts/build_apps.py --app pocketjs 会自动注入工具链环境并默认传入 -DPOCKETJS_APP=motions（与预编译固件 09_pocketjs-full.img 中的 480×272 Motion Lab 四页动效演示一致）。同时 samples/player/src/main.c 已采用 4-buffer Mailbox 换帧状态机，避免渲染循环覆盖正在扫描显示的帧缓冲。

版本与验证​

本工作区基于 Zephyr 4.5.0 分支完成构建，默认启用 G2D 与 RVV 加速（CONFIG_POCKETJS_G2D=y、CONFIG_POCKETJS_RUST_RVV=y、CONFIG_POCKETJS_BLEND_RVV=y）并支持触摸与串口键盘输入。

准备工作区​

配套 f101-zephyr 工作区已随包内置所需子模块、Bun 与带 rust-src 的 Rust nightly-2026-07-02（见 获取工程与编译烧录），直接通过 scripts/build_apps.py --app pocketjs 即可编译。

zephyr-components/pocketjs/samples/player/ 下的文件如下：

路径用途
app/默认 320×240 Solid 应用：main.tsx、app.tsx、manifest 与 host profile
bench/512×384 确定性 benchmark 及其 profile
pocket.host.480x272.jsonhero 等上游应用使用的 host profile
src/main.c包加载、guest／UI 初始化、tick 循环、RGB565 缓冲与显示
src/input.c触摸槽位、手势转按键及 UART 控制
CMakeLists.txt、Kconfig、prj.conf打包规则、样例选项与固件配置

构建与运行​

在配套工程根目录执行：

./.venv/bin/python scripts/build_apps.py --app pocketjs
./.venv/bin/python scripts/pack_full_img.py --app pocketjs

成功构建后，产物位于 build/pocketjs/zephyr/zephyr.elf、zephyr.bin 以及打包后的 zephyr-full.img。RAM 调试阶段可用 scripts/flash.py run pocketjs（或按Flash 布局与进阶调试方式一）直接载入内存启动，无需向 NOR 写入 bootloader。

播放器使用板级 DTS 选择的显示与触摸设备。yuzukineko 控制台为 UART1，PB0/PB1，波特率 115200。通过 scripts/build_apps.py --app pocketjs 构建时默认嵌入 480×272 的 Motion Lab（motions） 四页 6 宫格动效演示（左右滑动或串口按 A/D、Q/E 切换页面）；若直接执行不带 -DPOCKETJS_APP 的 west build，则构建 samples/player/app/ 下标有 PocketJS · Zephyr F101 的 320×240 最小 Solid 卡片。串口都会报告选中的 contract、尺寸和 tick 频率。

选择应用​

每个应用使用独立构建目录：

# 先将包内内置的 Bun 与 Rust 加入当前终端环境
export PATH="$PWD/tools/bun/bin:$PWD/tools/rust/cargo/bin:$PATH"
export RUSTUP_HOME="$PWD/tools/rust/rustup" CARGO_HOME="$PWD/tools/rust/cargo"

./.venv/bin/west build -b yuzukineko_base -d build/pjs-motions zephyr-components/pocketjs/samples/player -- -DPOCKETJS_APP=motions
./.venv/bin/west build -b yuzukineko_base -d build/pjs-hero zephyr-components/pocketjs/samples/player -- -DPOCKETJS_APP=hero
./.venv/bin/west build -b yuzukineko_base -d build/pjs-bench zephyr-components/pocketjs/samples/player -- -DPOCKETJS_LOCAL_APP=bench
./.venv/bin/west build -b yuzukineko_base -d build/pjs-card zephyr-components/pocketjs/samples/player

应用选择保存在 CMake 缓存中，增量构建时保留原选择，切换应用时使用独立目录。

选择源码逻辑画布Host profile／显示方式
POCKETJS_APP=motions（build_apps.py 默认）pocketjs/apps/motions/480×272pocket.host.480x272.json，integer-fit
未指定参数（CMake 默认）samples/player/app/320×240app/pocket.host.json，native
POCKETJS_APP=heropocketjs/apps/hero/480×272pocket.host.480x272.json，integer-fit
POCKETJS_LOCAL_APP=benchsamples/player/bench/512×384bench/pocket.host.json，native

只设置一个选择参数。同时存在时 POCKETJS_APP 优先。其他上游应用需要匹配的视口、能力及 profile。当前上游选择器始终传入 480×272 profile。

编写界面​

默认 app/main.tsx 挂载一个 Solid 组件：

import { mount } from "@pocketjs/framework/solid";
import App from "./app.tsx";

mount(() => <App />);

app/app.tsx 是最小卡片界面：

import { Text, View } from "@pocketjs/framework/solid/components";

export default function App() {
  return (
    <View class="w-full h-full bg-slate-950 items-center justify-center">
      <View class="w-64 h-24 rounded-xl bg-blue-600 items-center justify-center">
        <Text class="text-lg text-white font-bold">PocketJS · Zephyr F101</Text>
      </View>
    </View>
  );
}

修改后可在导出内置 Bun 与 Rust 环境变量后，使用独立构建目录重新执行 ./.venv/bin/west build -b yuzukineko_base -d build/pjs-card zephyr-components/pocketjs/samples/player。CLI 跟踪源码依赖，并将更新后的包嵌入固件。该最小卡片没有输入处理器，收到输入也不会改变静态画面。交互实现可参考 motions 或 bench 对 @pocketjs/framework/lifecycle、@pocketjs/framework/input 中 onButtonPress、onFrame 和 BTN 的使用。

这些组件及工具类属于 PocketJS，不提供浏览器 DOM、网页网络或 Node.js API。当前播放器在构建时嵌入一个包，不从 SD 加载 .pocket，也不提供热更新。HTML／CSS 页面渲染请看 LiteHTML。

Manifest 与 host profile​

app/pocket.json 选择入口、框架和视口，其中应用部分如下：

{
  "app": {
    "entry": "main.tsx",
    "output": "f101-player",
    "framework": "solid",
    "viewport": {
      "logical": [320, 240],
      "presentation": "native"
    }
  }
}

这是现有 manifest 的片段，不能代替必需的 pocket、标识／版本和 engine 字段。默认 manifest 使用 pocket: 2，要求 input.buttons 和 text.glyphs.baked。

配套的 pocket.host.json 描述 host 提供的能力：tickHz: 60、320×240 物理视口、接受的逻辑视口、rasterDensity: 1，以及 input.buttons、input.touch、text.glyphs.baked。修改应用视口时应同步修改 host profile。其中的 platform: "esp-idf"、form: "takeover" 和 schema 名称属于现有打包 contract，当前 Zephyr 接入应保留这些字段。它们不会在运行时选择另一个 RTOS。

CMake 先向 PocketJS CLI 传入 manifest／profile，再由 embed_package.py 生成固件使用的包数据与 host contract。.pocket、依赖计划和生成的 C／头文件／汇编文件位于构建树的 pocketjs/player/ 目录下。样式、字体和图像资源在 guest 启动前打包准备，文字需要包含应用使用的烘焙字形。

触摸与 UART 输入​

样例接收 zephyr,touch 的多指槽位，并把屏幕坐标映射到居中的逻辑画布。画布放得下时优先整数倍缩放，否则保持宽高比缩小。画布外的触摸不传入。首指滑动还会产生方向键，轻点产生 Cross。

没有触摸屏时可用 UART 控制台按键：

输入动作
W / S / A / D上／下／左／右
J 或空格 / KCross / Circle
U / ISquare / Triangle
Q / E左／右肩键
Enter / Tab 或小写 bStart / Select

除小写 b 快捷键外，字母均接受大小写。串口终端没有松键事件，样例将每次按键保持为 110 ms 脉冲。按键位或手指数变化时会输出输入日志。应用必须处理对应输入，单有输入日志不能证明屏幕交互正确。

显示、内存与时钟配置​

主循环采样输入、调用 pocketjs_ui_turn()、绘制脏区条带、提交逐缓冲 target 状态并刷新变更范围的 cache。独立 video 线程通过 display_sunxi_show_rgb() 显示最新完成的 RGB565 图像。四张动态申请、64 字节对齐的缓冲通过 Mailbox 所有权状态（追踪当前在屏、提交中与待提交槽位）协同工作，既允许显示持有图像时主线程持续绘制并按缓冲保留独立脏区历史，又避免覆盖正在扫描输出的画面。

栅格密度为 1 时，四张缓冲在默认应用占用 614,400 字节，bench 占用 1,572,864 字节，尚未计入对齐。估算内存时还需加上 QuickJS 堆、Rust UI 对象、栅格／暂存缓存及线程栈。4 MiB guest 上限并非应用总内存上限。

配置样例默认值含义
CONFIG_POCKETJS_GUEST_HEAP_LIMIT4194304QuickJS 堆上限，字节
CONFIG_MAIN_STACK_SIZE9830496 KiB 主栈，播放器将 JavaScript 限制为 64 KiB
CONFIG_HEAP_MEM_POOL_SIZE262144Zephyr 内核堆池，与 libc arena 分开
CONFIG_COMMON_LIBC_MALLOC_ARENA_SIZE-1libc arena 使用剩余可用内存
CONFIG_SAMPLE_POCKETJS_CPU_MHZ960请求的 CPU 时钟，0 保持 loader 设置
CONFIG_POCKETJS_TURN_STATSyscript／tick／draw 与脚本指令统计
CONFIG_SAMPLE_POCKETJS_PROFILE关闭可选主线程程序计数器采样

样例按 72 MHz 步进提高 CPU 频率，并执行小块校验负载，不能替代完整 PSRAM 稳定性测试。需按 loader 时钟测量时设置 CONFIG_SAMPLE_POCKETJS_CPU_MHZ=0。记录性能结果时应注明时钟、应用、视口和加速配置。G2D／RVV 选项见组件配置。

Benchmark 与统计​

POCKETJS_LOCAL_APP=bench 按以下顺序运行 17 个场景：

idle fill round alpha text rotate image mixed spin calls objs scroll stretch zoom move kf still

每个场景持续 360 ticks，运动由 tick 数决定，自动序列最终停在 still。按 D 切到下一场景，A 切到上一场景，同时停止自动选择。按 J 切换自动选择。在 bench/app.tsx 中把 LOOK 设为场景名，可固定该负载。切换场景会输出 BENCH 标记。

播放器约每五秒报告 tick／picture 数、平均／最大 busy 耗时、turn／render／cache flush 耗时、G2D／软件操作数及脏区像素。启用 turn 统计后，还会报告 script／tick／draw 耗时和脚本 cycles／instructions／IPC。ticks 统计 UI turn，pictures 统计有脏区且已提交的更新。video 线程可能跳过被替代的图像，两者均不能直接视为实际显示 FPS。60 Hz contract 是调度目标，不是性能保证。

常见问题​

现象检查项
缺 PocketJS／QuickJS 文件或 Bun 包初始化两个固定版本子模块，安装 CLI 依赖
Cargo target、rust-src 或 ABI 错误检查固定 nightly、FPU／RVV target 选择和 C／Rust ABI；切换版本后使用新构建目录
包选择或资源装载失败核对 manifest／profile，一起重新生成包数据和 contract
display not ready 或 show_rgb failed检查板级 DTS、所选显示和 RAM 镜像启动路径
输入日志变化但卡片不动samples/player/app/ 最小卡片是静态界面，请改用 motions 等交互应用或添加处理器
触摸位置偏移核对物理屏尺寸、逻辑画布、居中／缩放和触摸驱动坐标
分配失败、栈错误或复位计入原生对象／缓冲内存、实际 RAM 区域和所属线程栈，降低负载并检查时钟稳定性
tick 速率低或 G2D 计数为零对比脚本与渲染耗时及脏区面积，小操作和部分混合由 CPU 处理

API 有效期规则与主机栅格检查见 PocketJS 组件接入。
